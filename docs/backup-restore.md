# 备份与恢复

备份包包含 TS3 的**服务器身份**（私钥 / 证书）、SQLite 数据库和 `files/`。
还原后客户端看到的仍是同一个服务器身份，收藏地址不会因为换机器而失效（地址本身仍需可达）。

> 备份包等同于服务器身份凭证：请按机密文件保管（面板创建的目录 `0700`、文件 `0600`），
> 不要上传到公开网盘或提交到 Git。

---

## 1. 备份里有什么

实例目录（默认 `/srv/ts3/<id>/`）会被整体打包：

```text
<id>/
├── ts3server.sqlitedb      # 频道、权限、客户端数据
├── files/                  # 上传的文件、图标等
├── logs/                   # 只保留最近 7 天的日志
├── .panel.json             # 实例元数据副本（便于手工迁移）
└── ...                     # 身份密钥等其他运行时文件
```

规则：

- `logs/` 下修改时间超过 7 天的文件会被排除，避免备份包膨胀。
- 备份包先写 `.tmp` 再 `rename`，中断不会留下半个“看起来正常”的包。
- 备份前检查剩余磁盘：不足实例目录大小的 **2 倍**时直接失败，不产生半成品。
- 备份文件名：`<实例 id>-<YYYYmmdd>-<HHMMSS>[-n].tar.gz`，位于 `{instance_root}/.backups/`。
- 备份期间会短暂停止容器，完成后自动启动；若启动失败，状态会在详情页体现。

## 2. 手动备份

面板 → 实例详情 → 「备份」→「立即备份」。完成后可在备份列表下载。

HTTP 接口（写接口需要 `X-Requested-With: ts3panel` 和登录 Cookie）：

```bash
curl -X POST http://127.0.0.1:8899/api/instances/<id>/backup \
  -H 'X-Requested-With: ts3panel' -b cookies.txt

# 列出该实例的备份
curl http://127.0.0.1:8899/api/instances/<id>/backups -b cookies.txt

# 流式下载（服务端不会把整包读进内存）
curl -OJ 'http://127.0.0.1:8899/api/instances/<id>/backup?file=<文件名>' -b cookies.txt
```

手动备份**不参与滚动清理**，不会被自动删除。面板会显示每份备份的占用空间，请自行清理不需要的包。

## 3. 自动备份计划

设置页 →「备份计划」，或直接改 `config.toml`：

```toml
[backup]
enabled = true
mode = "daily"        # daily | interval
daily_at = "04:30"    # mode=daily，服务器本地时区
interval_hours = 24   # mode=interval
retention = 7         # 只保留最新 7 份自动备份
```

- 调度器是进程内 ticker，不依赖系统 cron；修改后无需重启，保存即生效。
- 面板重启后按配置恢复，不会重复触发已完成的周期，也不会漏掉应执行的下一次。
- 每轮执行后按 `retention` 删除最旧的**自动**备份；手动备份不在清理范围内。
- 设置页显示「上次成功时间 / 下次执行时间」。
- 自动备份失败会在日志中记录原因（磁盘不足、容器停止失败等），不会留下坏包。

## 4. 恢复

### 4.1 同机恢复

1. 实例详情 →「备份」→ 选择备份包 →「恢复」；
2. 面板先校验包结构（必须含 `ts3server.sqlitedb`），再停止容器；
3. 把当前数据目录移到临时目录，解压新包；解压失败会回滚原目录；
4. 启动容器并确认进入 running；
5. 失败时原目录仍在，可在详情页重试或查看日志。

也可以上传本地 `.tar.gz`：面板会先把上传文件导入备份列表，再执行恢复，因此可以重试。

### 4.2 跨机器恢复

1. 在新机器安装**同版本** ts3panel 并完成初始化；
2. 在新机器创建一个实例，**子域名保持一致**（实例 ID 由子域名前缀生成，必须相同才能对上）；
3. 把旧机器的备份包上传到该实例并恢复；
4. 检查端口、Docker 标签、DNS 记录；
5. 若域名变了，在实例详情重新绑定 A + SRV。

> 新实例创建时会占用一组端口；恢复不会改变端口分配。旧机器和新机器不要同时对外提供同一个身份，
> 否则客户端会看到两台“同一服务器”。

### 4.3 恢复后 token 不会回来

备份包**不保存管理员 token**。token 是首次启动日志里的一次性 Privilege Key，可能已被使用。
恢复后：

- 服务器身份、频道、权限、文件都还在；
- 需要 Server Admin 权限时，在 TS3 客户端重新获取 Privilege Key，或通过已有管理员账号授予；
- 面板详情页的 token 字段可能为空，这是预期行为，不是恢复失败。

## 5. 磁盘与保留策略

```bash
du -sh /srv/ts3/* /srv/ts3/.backups/* 2>/dev/null | sort -h
df -h /srv/ts3
```

- 手动备份：不自动删除，自己 `rm` 或通过面板删除。
- 自动备份：按 `retention` 保留最新 N 份。
- 备份前磁盘检查按实例目录大小的 2 倍估算；目录很大时请预留足够空间。
- 不建议把 `.backups` 放在网络盘或跨文件系统挂载点上：备份使用同目录临时文件 + rename，
  跨文件系统 rename 会失败。

## 6. 手工迁移（不走面板）

紧急情况下可以直接拷目录：

```bash
systemctl stop ts3panel
docker stop ts3-<id>            # 只停自己标签的容器
tar -C /srv/ts3 -czf /root/ts3-<id>.tar.gz <id>
# 新机器：解压到 /srv/ts3/<id>，确认权限，再启动容器
```

注意：

- 容器的数据目录属主由镜像 entrypoint 负责，手工拷贝时保留属主/权限（`tar -p`）。
- 直接拷目录不会同步 `state.json` 里的备份记录和 DNS 记录 ID；面板可能显示不一致。
- 不要用 `docker cp` 拷贝正在写入的 SQLite 数据库，先停容器。
